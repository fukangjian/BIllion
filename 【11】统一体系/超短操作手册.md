# 超短操作手册（1-5 天）

> **定位**：用 Invest 系统指导 1-5 天超短交易的固定动作清单，与价值投资层兼容。
> **原则**：系统负责筛选、计算、风控、验证；人负责盘中买卖时机；纪律负责执行。
> **关联文档**：[[投资体系_V5.0]] · [[基金经理日常工作流]] · [[买入卡模板]] · [[周报模板]]

---

## 〇、系统能力边界（先读这个）

| 系统能做 | 系统不做 |
|---|---|
| 盘前热点筛选（涨停/连板/强板块领涨 → 热点池） | 盘中分钟级实时信号 |
| 交易计划参数（触发价、止损、仓位股数） | 自动下单（永远人工执行） |
| 入场合规闸门（账户限额、簇限额、回撤收紧） | 打板、集合竞价策略 |
| 信号自动结算与胜率验证（HOT-S，5 日强制结算） | 预测热点持续性 |

**一句话**：系统告诉你「今天该盯哪几只、买多少、错了在哪走」；盘中买卖点是你的工作。

---

## 一、资金分层（兼容价值投资）

| 层 | 账户 | 占比（默认，可调） | 策略 | 说明 |
|---|---|---:|---|---|
| 价值层 | 核心 | 50-60% | STR-C 核心复利（1-5 年） | 低频人工决策，**不参与超短** |
| 超短层 | 事件 | 40-50% | S1-A 通道 + 热点池（1-5 天） | 单笔风险 ≤0.35%，单票仓位 ≤4% |
| 试错层 | 实验 | 包含在超短层内 | 新打法小仓验证 | 单笔风险 ≤0.5%，仓位 ≤1% |

**风险隔离是自动的**：

- 合规闸门按账户类型强制限额，超短层亏损不会击穿价值层额度；
- 回撤状态升档自动收紧：Defensive 禁止事件/实验开新仓，Review 全部停止（对应 V5.0 §6）；
- 超短层盈利可按月手动转入核心账户复利。

## 二、盘前 SOP（30-40 分钟，与系统输出一一对应）

```text
python run_all.py   （或 08:30 定时服务自动跑）
```

1. **看市场状态**（扫描报告第一节）——决定今天做不做、做多少：
   - **A/B**：可按计划执行；
   - **C（震荡轮动 = 热点快速轮换的环境）**：超短仓位减半，只做连板龙头和主线板块候选；
   - **D**：停止开新仓，只管理已有持仓；
   - **情绪相位**（2026-09 起新增，超短生态口径，与 A/B/C/D 互补）：**冰点/退潮 → 超短禁开新仓**（建仓闸门高级违规，9:25 竞价口径自动收紧，二板池自动缩至前 3 只）；**修复/高潮 → 风险减半**（建议股数自动 ×0.5）；**发酵 → 正常开仓**。
2. **定主线**：板块相对强度 Top 5（第四节）+ 涨停/连板统计（第五节）互相印证——涨停家数集中的板块 = 当日情绪主线。
3. **定候选（最多 3-5 只）**：从「连板股」和「热点池突破候选」表中选——候选表含**名称与推荐分析**（系统按买入规则 8 条自动核对 ①板块Top5 ②涨停家数增加 ③前排 ④放量 ⑦大盘环境，按满足条数排序；⑤⑥盘中确认、⑧事件催化最重要——系统读公告自动判定（配置 LLM Key 后），未配置时报告列出公告标题自行核对），写下：触发价、止损价、失效条件（什么情况下这个逻辑就不成立了）。
4. **算仓位、建仓**：
   - `python review/cli.py from-scan <代码>` 先打印突破参数与建议（不落库）；
   - 确认后 `python review/cli.py from-scan <代码> --execute --account 事件` 一键建仓（自动算仓位 → 合规闸门 → 写库 → 生成买入卡）；
   - from-scan 现支持热点池突破候选（系统 HOT-S，默认账户 事件）：仅热点信号时自动按 HOT-S 建仓，同股同时有波段信号时用 `--system HOT-S` 显式选择；
   - 非扫描来源的候选用 `python position_calculator.py -s <代码> -e <触发价> --stop <止损价> -t 事件` 算股数，再用 `review/cli.py add` 落库。
5. **管持仓**：扫描报告顶部「持仓监控」区块的止损/退出警报 → 写入今日执行计划。

---

## 三、盘中纪律（超短生死线）

- **只执行盘前计划**。盘中新发现的热点：30 分钟冷却 + 写下信息来源/催化/失效条件/止损/仓位，仍成立才允许 ≤0.25% 风险小仓。
- **止损不扩大**，触发即走，不讨价还价。
- **第 5 个交易日强制离场**（与系统 HOT-S 信号强制结算同步，你的战绩会被如实统计）。
- 不追盘中直线拉升超过计划买入价的票——错过就错过，市场明天还开门。
- 连板一字买不进：放弃，不排队、不隔夜委托赌开板。

---

## 四、盘后 30 分钟

- 成交录入/平仓更新：`python review/cli.py list` 核对，`update` 补实际退出价（`--exit-time` 记退出时间）。
- 券商成交批量导入：`python review/cli.py import --file 成交.md --year 2026`（先 `--dry-run` 演练；名称解析失败用 `--symbol-map 名称=代码,...` 手动指定；落库含成交时间戳，供纪律审计用）。
- 卖出前先过卖点检查单：`python review/cli.py sell-check <代码>`（止损/退出通道警报 + 持有天数 + HOT-S 5 日倒计时 + 是否在热点池 + 建议挂单价=收盘×0.99，挂低 1% 防挂高未成交）。
- 算 R、标记违规（追价/扩止损/超仓/无计划交易）。
- 写明日持仓方案：每笔持仓的止损位、加减仓/退出条件、不操作条件。

## 五、每周验收（数据说话，别靠感觉）

```powershell
python pipeline/signal_tracker.py stats --days 90   # 看 HOT-S 胜率/平均R/期望值/PF
python review/cli.py weekly                          # 周报（含信号验证、纪律审计节）
```

- **周报/月报由调度器自动生成**（`ENABLE_SCHEDULER=true` 时：每周五 15:45 周报、每月最后一天 16:00 月报），均含「纪律审计」节——追高接回、闪电换仓、禁买板块、无止损、非系统交易逐笔列出，先处理「高」严重度。

- **样本 < 5 之前仓位减半**（系统统计自动标注「样本不足」）。
- HOT-S 期望值连续两周为负 → 停用热点池信号，只做 S1-A 波段，回头复盘哪一步错了。
- 胜率 vs 盈亏比失衡（如胜率 <35% 且平均R <0）→ 检查是否入场太追、止损太宽。

## 六、与价值层的协同规则

- 两个层级的额度互不挪用；核心账户的钱永远不补超短的亏损。
- 同一只股票可以同时存在核心仓（长持）与事件仓（超短），交易系统分别记录、分别报警。
- 超短持仓的止损/退出警报与价值仓一起在盘前「持仓监控」区块呈现，不会漏。

---

## 七、常见问题

- **热点池为空**：数据源降级（看 run_all 日志）。用板块排名 + 人工涨停复盘代替，次日自动恢复。
- **C/D 状态特别想做**：仓位减半（C）或禁止（D）。不要和系统对着干——回撤升档后闸门会替你强制停手，代价更高。
- **信号和感觉冲突**：先按信号小仓执行，盘后复盘再争论。感觉需要对的时候，用 90 天信号统计来证明。
- **创业板（300/301）已于 2026-08-07 放开**：`BANNED_BOARD_PREFIXES` 默认置空，闸门与纪律审计不再拦截；机制保留（重新配置前缀即恢复）。

## 八、龙头评分自动化（2026-08-07 起）

《如何识别真假龙头》三维验证的可量化落地：盘前扫描对热点池突破候选逐条打「龙头评分」（`pipeline/dragon_head.py`，离线数据，无未来函数），S/A/B 级候选进入「明日操作计划」龙头组（置顶于趋势候选之前）与 UI 控制台。

| 维度 | 分值 | 量化口径 |
|---|---|---|
| 身位 | 30 | 板块内连板最高（lbc≥2）→ 30；首板且首次封板时间板块内前 3 → 20；跟风 → 8 |
| 梯队 | 20 | 板块涨停 ≥5 家且连板层级 ≥2 → 20；3-4 家 → 12；1-2 家（独木难支）→ 4 |
| 强度 | 20 | 一字板 → 4（无量）；换手率 15-35% → 10 / 5-15 或 35-50% → 6；封板资金 ≥1 亿 → 10 / ≥5000 万 → 6；炸板 ≥3 次 → 强度减半 |
| 逻辑 | 20 | 证据分级：⑧公告催化满足 → 20；有同花顺涨停归因（如「CRO+创新药+国资入主」，市场归因待验证）→ 12；待人工核对 → 8；无催化且无归因 → 0 |
| 情绪 | 10 | 当日涨停 ≥50 家 → 10；30-49 → 6；20-29 → 3；<20 → 0（冰点，独龙难活） |

**等级段**：S ≥ 80 / A 65-79 / B 50-64 / C < 50（与 V5.0 凸性评分段一致）。

**系统辨龙（2026-08-07 起）**：量化五维评分之上，`research/dragon_reasoner.py` 用 Kimi K2.6（task_type=reasoning，兼顾推理能力与费用）对候选做深度推理，直出「真龙头/疑似龙头/跟风/伪龙头」判定 + 置信度 + 引用数据的判定理由 + 本期直选龙头（primary）+ 明日板块聚焦（sector_focus：持续/一日/退潮，架构A 顶层逻辑梳理，与个股判定同一次调用完成，不增调用次数）；防编造护栏（symbol 必须候选内、verdict 枚举、confidence 截断），无 Key/失败降级为纯量化评分排序并标注（UI 红色横幅明示）。**个股证据链深挖（2026-08-07 起）**：`research/evidence_chain.py` 对量化分 Top 3 候选逐股联网深挖（K2.6 + 搜索，当日缓存）：引爆点、链式推导、正面/反面证据、关联个股、行业地位，注入辨龙头推理；报告与 UI 有「🔍 个股证据链」展示。

竞价监控/盘中异动提醒属盘中实时范畴，本系统不做；龙虎榜席位评分、炸板回封判定列后续。

**9:25 竞价核对清单**（架构A 盘中半边的离线落地）：龙头候选每只附竞价去留规则——高开 3%~5% 且放量→按计划执行；一字板→不追看龙二；低开→剔除。在扫描报告「明日操作计划」与 UI 控制台展示。

**事件日历（逻辑链前瞻，2026-08-07 起）**：`research/event_calendar.py` 主动探查未来 30 天关键事项——个股结构化事项（财报预约披露/限售解禁，免 LLM）+ 板块行业事件（Kimi K2.6 联网搜索，政策/会议/数据/产品窗口，当日缓存）。注入龙头深度推理作证据，并在计划与 UI 的「📅 未来 30 天关键事项」区块展示；无 Key/联网失败降级为仅结构化事项。
