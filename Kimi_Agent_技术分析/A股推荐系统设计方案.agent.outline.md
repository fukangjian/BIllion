# 《职业投资自动化A股推荐系统设计方案》大纲

- 目标读者：本人（散户，3.25万本金，目标3年成为基金经理，具备Python/嵌入式/n8n能力）
- 文档性质：可落地的技术设计文档，非概念文章；每章给出表结构、接口名、伪代码或配置示例
- 语言：中文；总字数约9000–11000字
- 个性化主线：把用户手写交易体系逐条工程化（七步分析框架→事件引擎；买入8条件→评分卡；卖出4触发→监控；纪律错误→系统强制约束；案例方法论→复盘库）
- 图表规范：架构图用ASCII分层框图，不用mermaid（便于docx转换）；多用表格
- 引用：调研结论在正文就近标注来源（如：来源：tushare.pro文档，2026），文末附参考资料清单

- 1.2 设计目标与边界：纯自用荐股+纪律执行系统；不全自动下单（资金门槛）；合规边界一句话
- 1.3 总体架构：ASCII分层图（数据层→信号层→决策层→执行层→复盘层）+ 各层职责表
- 1.4 技术选型总表：Python/akshare/tushare/baostock/SQLite/DeepSeek V4-Flash/n8n/钉钉机器人/券商条件单

## 第3章 信号层：交易体系工程化（约2400字，核心章）【Round 1】
- 3.1 七步分析框架 → 事件驱动引擎流水线：快讯采集→DeepSeek结构化抽取(事件/方向/强度)→受益链映射(事件→商品→板块→个股)→成分股白名单校验（防LLM幻觉，三段式）→观察池入库；给出DeepSeek prompt示例与JSON输出schema
- 3.2 买入8条件 → 量化评分卡：逐条给出量化口径（板块涨幅前5=sector_daily排名；涨停家数增加=limit_pool计数环比；前排=板块内涨幅/成交额分位；放量突破=量比+换手率；涨停承接=炸板回封/封单额；次日无高开低走；分时均价线拉回；事件催化=3.1引擎输出）+ 触发规则（≥4条=全仓信号，2-3条=观察）+ 伪代码
- 3.3 观察池管理：生命周期（候选→观察→可买→持仓→卖出→归档）状态机
- 3.4 与手写规则对照表：笔记原文→系统实现→防呆价值

## 第4章 风控与执行层（约1800字）【Round 1】
- 4.1 卖出风控4触发自动监控（停火类事件→LLM判定；板块破5日线；龙头跌停；商品连跌2日+资金流出2日）→钉钉告警分级
- 4.2 纪律强制执行器（本方案灵魂）：
  - 9:15–9:30 信号锁定期（只看计划不操作，对应洗盘教训）
  - 禁买名单（创业板/科创板默认禁买，可配置）
  - 后排拦截（非板块前N名禁止生成买入计划）
  - 挂价规则（卖出默认挂低1%，对应"低1分钱没成交"教训）
  - 交易计划卡：每次操作前系统强制生成"买点+卖点+仓位"卡片，未生成不推送（对应"操作前先写下买点和卖点"）
- 4.3 执行通道三阶段：现阶段券商APP条件单（零门槛半自动，含条件单设置示例）→本金达标后miniQMT→远期全自动；合规报告义务提醒（向券商报备自研软件）
- 4.4 告警与推送：n8n工作流 + 钉钉机器人消息模板（用户已有n8n基础）

## 第5章 复盘案例库与MVP路线图（约1500字）【Round 2】
- 5.1 自动复盘：成交对账导入→每笔交易规则符合度评分→情绪操作标记（如计划外交易、9:30前操作）
- 5.2 案例库：trade_case表设计，每周复盘报告自动生成（钉钉长文档/邮件），对应"积累二三十个案例"方法论
- 5.3 MVP路线图：P0(2周,板块监控+评分卡+钉钉推送)→P1(3周,事件引擎+风控告警)→P2(2周,复盘库+周报)→P3(远期,回测+miniQMT)；每阶段验收标准
- 5.4 事件日历机制：以8月机器人大会为例（利好兑现前8/10-8/17关注，事件当天不追高）
